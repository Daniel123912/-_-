## 1. Концепция продукта (Vision)

### 1.1. Проблема

Дети 7–11 лет получают карманные деньги и сталкиваются с выбором «купить сейчас / отложить / нужное vs желаемое», но редко имеют безопасную игровую среду, где:

- финансовые решения **видимы** через последствия;
- ошибка **обучает**, а не наказывает стыдом;
- взрослый может **наблюдать прогресс** без сбора персональных данных.

### 1.2. Решение

Офлайн мобильное приложение: ребёнок ухаживает за виртуальным питомцем **Финни**. Состояние и рост питомца зависят от планирования бюджета, покупок, накоплений и выполнения учебных заданий.

**Ценностное предложение одной фразой:**  
«Играй → планируй деньги → учись на результате периода → питомец растёт от разумных решений».

### 1.3. Цели MVP (измеримые)

| ID | Цель | Критерий успеха |
|----|------|-----------------|
| G1 | Покрыть обязательный сценарий ТЗ (Приложение А) | 11 шагов демо без тупиков |
| G2 | Научить различать нужное / желаемое / накопление | ≥1 полный цикл план → факт |
| G3 | Работа без сети и без аккаунтов | Release без INTERNET; прогресс локально |
| G4 | Адаптация к возрасту | 3 трека сложности контента |
| G5 | Воспроизводимость для экспертов | Демо-режим + сброс профиля |

### 1.4. Вне scope (осознанно)

- Реальные платежи, реклама, IAP
- Аккаунты, облако, мультиустройство
- Социальные чаты, рейтинги давления
- iOS как обязательная платформа сдачи
- Сбор ПДн, аналитика третьих сторон

Подробнее: [`limitations_roadmap.md`](limitations_roadmap.md).

## 2. Заинтересованные стороны (Stakeholders)

| Стейкхолдер | Интерес | Как удовлетворяем |
|-------------|---------|-------------------|
| Ребёнок 7–11 | Играть, растить питомца, не «скучная школа» | Механика питомца, мягкий fail, награды |

| Разработчик команды | Понятные правила и расширение контента | Domain layer + JSON-контент |

## 3. Акторы системы

```
                    ┌─────────────────┐
                    │   Content JSON  │  (не актор, источник данных)
                    └────────▲────────┘
                             │
┌──────────┐   действия   ┌──┴──────────┐   save/load   ┌──────────────────┐
│ Ребёнок  │─────────────►│  Приложение │◄─────────────►│ SharedPreferences│
└──────────┘              │  «Финни»    │               └──────────────────┘
                          └──┬──────────┘
┌──────────┐   барьер +     │
│ Взрослый │───────────────►│
└──────────┘   настройки    │
                            │
┌──────────┐   install/run  │
│ Эксперт  │───────────────►│  (тот же клиент, часто с demoMode)
└──────────┘
```

| Актор | Описание | Права |
|-------|----------|-------|
| **Ребёнок** | Основной пользователь | Онбординг, питомец, бюджет, магазин, копилка, задания, учёба, итог периода |
| **Взрослый** | Родитель / опекун | Прогресс, демо-режим, звук, начисление монет, челлендж, сброс |
| **Эксперт** | Проверяющий по ТЗ | Как взрослый + сценарий Приложения А; не отдельный UI |

Система **не имеет** серверного актора: backend отсутствует.

## 4. Контекст и границы системы

### 4.1. Контекст (C4 Level 1)

```
┌──────────────────────────────────────────────────────────┐
│                     Граница системы                       │
│  Flutter-клиент Android (опц. Web Chrome для демо)        │
│  • UI features                                           │
│  • GameController + GameEconomy                          │
│  • ContentLoader (assets/content/*.json)                 │
│  • ProfileRepository (SharedPreferences)                 │
└──────────────────────────────────────────────────────────┘
         ▲                              ▲
         │ install APK / flutter run    │ (нет исходящего сети в release)
         │                              │
   Устройство пользователя         Внешние системы: НЕТ
```

### 4.2. Входы / выходы

| Вход | Источник | Выход | Получатель |
|------|----------|-------|------------|
| Тапы / ввод имён | Ребёнок | Обновлённый профиль | Локальное хранилище |
| Выбор плана / ответов | Ребёнок | Feedback, статы питомца | UI |
| JSON контент | Ассеты сборки | Каталог товаров/квестов/уроков | ContentLoader |
| Сброс / демо | Взрослый | Чистый профиль / ускоренные таймеры | UI |

### 4.3. Предположения

1. Устройство Android API 26+, ОЗУ ≥ 3 ГБ.
2. Пользователь не обязан иметь интернет.
3. Один локальный профиль на установку (гостевой).
4. Учебный контент корректен относительно схемы моделей Dart.

### 4.4. Ограничения

1. Только клиентская логика; формулы экономики — single source of truth в `lib/domain/economy.dart`.
2. Нет синхронизации между устройствами.
3. Время периода в обычном режиме сжато (минуты), не «реальные недели».

## 5. Объектная область (предметная модель)

Ключевые понятия (кратко; полный глоссарий — §9):

| Понятие | Смысл в продукте |
|---------|------------------|
| **Период** | Игровая «неделя/цикл»: план → игра → итог |
| **План бюджета** | Распределение баланса по корзинам до трат |
| **Факт** | Фактические траты и отложения за период |
| **Корзина** | Mandatory / optional / savings / gift |
| **Игровая валюта** | Монеты на «кармане» (`balance`) |
| **Копилка** | `savingsBalance` + выбранная цель |
| **Трек возраста** | junior / middle / senior — фильтр сложности |
| **Стадия питомца** | 1 Малыш → 2 Растущий → 3 Чемпион |
| **Хороший период** | Правило `wasGoodPeriod` (обязательное + копилка или близость к плану) |

## 7. Нефункциональные требования (NFR)

| ID | Категория | Требование | Как проверяем |
|----|-----------|------------|---------------|
| NFR-01 | Производительность | Холодный старт UI roughly ≤ 5 с на целевом устройстве | [`device_test_report.md`](device_test_report.md) |
| NFR-02 | Офлайн | Основной цикл без сети | Airplane mode, M9 |
| NFR-03 | Приватность | Нет сбора ПДн, нет лишних permission в release | Manifest + [`privacy_permissions.md`](privacy_permissions.md) |
| NFR-04 | Надёжность прогресса | Kill/reopen сохраняет профиль | M6 |
| NFR-05 | Этичность | Нет «смерти» питомца, нет штрафа за пропуск дня | UX review |
| NFR-06 | Доступность (базовая) | Текст feedback; звук отключаем; подтверждения destructive | [`ux_accessibility.md`](ux_accessibility.md) |
| NFR-07 | Сопровождаемость | Контент отделён от логики (JSON) | Добавление квеста без смены формул |
| NFR-08 | Тестируемость | Юнит-тесты домена | `flutter test` |
| NFR-09 | Портируемость демо | Web Chrome для просмотра UI | `flutter run -d chrome` |
| NFR-10 | Установка | Установка APK / adb на Android 8+ | [`build_guide.md`](build_guide.md) |

## 8. Риски и меры

| Риск | Вероятность | Влияние | Мера |
|------|-------------|---------|------|
| Эксперт не успевает из‑за кулдаунов | средняя | высокое | Демо-режим по умолчанию / инструкция |
| Потеря прогресса при сбое записи | низкая | среднее | Backup-ключ профиля |
| Контент слишком сложен для 7–8 | средняя | среднее | Фильтр `ageTracks` + easy only |
| Несоответствие docs и кода | средняя | высокое | Матрица + тесты экономики |
| APK не подписан под стор | высокая (хакатон) | низкое для демо | Debug/release local; roadmap RuStore |

## 9. Глоссарий

| Термин | Определение |
|--------|-------------|
| **MVP** | Минимально жизнеспособный прототип по ТЗ хакатона |
| **Гостевой профиль** | Локальный профиль без регистрации |
| **Онбординг** | Вводные экраны о трёх типах решений |
| **AgeTrack** | Трек сложности: junior / middle / senior |
| **PeriodPhase** | `planning` → `playing` → `summary` |
| **ExpenseKind** | Тип товара: обязательное / желаемое / подарок |
| **PlanFactReport** | Результат сравнения плана и факта |
| **wasGoodPeriod** | Флаг «хорошего» периода для роста стадии |
| **demoMode** | Ускорение таймеров для демонстрации |
| **nextAction** | Подсказка «сейчас важно» на главном |
| **sort_buckets** | Интерактив: разложить карточки по корзинам |
| **claimGoal** | Получение награды за достигнутую цель копилки |
| **soft fail** | Ошибка без закрытия задания; можно исправить |
| **SharedPreferences** | Ключ-значение хранилище Android/Flutter |
| **ContentLoader** | Парсер JSON → `GameContent` |

## 10. Критерии готовности системы (Definition of Done MVP)

1. Все пункты матрицы 2.5.1–2.5.14 в статусе «готово» или явно «частично» с планом.
2. Юнит-тесты экономики зелёные.
3. Демо-сценарий Приложения А проходит в демо-режиме.
4. Сопроводительная документация §5 собрана (MD + DOCX).
5. Release APK собирается; permission-профиль соответствует политике офлайн.
