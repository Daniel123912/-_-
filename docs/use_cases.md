# Каталог Use Case

**Система:** Питомец Финни  
**Акторы:** Ребёнок, Взрослый, Эксперт (как Взрослый + сценарий проверки)  
**Связь:** UC → FR в [`functional_spec.md`](functional_spec.md)

Формат: краткий шаблон RUP/UML, достаточный для приёмки MVP.

## UC-01. Пройти онбординг

| Поле | Содержание |
|------|------------|
| **Цель** | Понять три типа решений до игры |
| **Предусловие** | Профиль отсутствует |
| **Триггер** | Первый запуск |
| **Основной поток** | 1. Система показывает экраны онбординга. 2. Пользователь листает/закрывает. 3. Система переводит к созданию питомца. |
| **Постусловие** | Онбординг пройден в сессии; профиль ещё не создан |
| **Альтернативы** | — |

---

## UC-02. Создать питомца

| Поле | Содержание |
|------|------------|
| **Цель** | Получить персонального питомца и профиль |
| **Предусловие** | Онбординг завершён / профиль null |
| **Основной поток** | 1. Выбрать цвет / глаза / дополнение. 2. Ввести имена. 3. Выбрать трек. 4. Подтвердить. 5. Система создаёт `PlayerProfile.fresh`, сохраняет, открывает главный. |
| **Постусловие** | Профиль существует; фаза `planning`; стартовый баланс трека |
| **Альтернативы** | A1: пустые имена → валидация, остаёмся на экране |

---

## UC-03. Посмотреть главный экран

| Поле | Содержание |
|------|------------|
| **Цель** | Ориентироваться: деньги, питомец, следующий шаг |
| **Предусловие** | Профиль загружен |
| **Основной поток** | 1. Система показывает баланс, копилку, статы, питомца. 2. Показывает `nextAction`. 3. Пользователь выбирает раздел. |
| **Постусловие** | Без изменения данных (если только просмотр) |

---

## UC-04. Составить и подтвердить план бюджета

| Поле | Содержание |
|------|------------|
| **Цель** | Зафиксировать распределение денег на период |
| **Предусловие** | Фаза `planning` |
| **Основной поток** | 1. Открыть план. 2. Распределить по корзинам (или взять рекомендацию). 3. Подтвердить. 4. Система проверяет правила. 5. Фаза → `playing`. |
| **Постусловие** | `BudgetPlan` сохранён; задания периода доступны |
| **Альтернативы** | A1: total > balance → отказ. A2: mandatory ≤ 0 → отказ. |

---

## UC-05. Купить товар

| Поле | Содержание |
|------|------------|
| **Цель** | Потратить монеты на товар нужного/желаемого типа |
| **Предусловие** | Фаза `playing` |
| **Основной поток** | 1. Открыть магазин. 2. Выбрать товар. 3. Подтвердить покупку. 4. Система списывает баланс, пишет факт, меняет статы, сохраняет. |
| **Постусловие** | Товар учтён; feedback показан |
| **Альтернативы** | A1: не хватает монет → отказ + текст. A2: не `playing` → покупка недоступна. |

---

## UC-06. Пополнить копилку

| Поле | Содержание |
|------|------------|
| **Цель** | Отложить часть баланса |
| **Предусловие** | `playing`; amount > 0; canAfford |
| **Основной поток** | 1. Указать сумму. 2. Подтвердить. 3. `balance` ↓, `savingsBalance` ↑, `fact.saved` ↑. |
| **Альтернативы** | A1: нехватка → отказ |

---

## UC-07. Снять с копилки

| Поле | Содержание |
|------|------------|
| **Цель** | Вернуть деньги из копилки на баланс |
| **Предусловие** | `playing`; в копилке достаточно |
| **Основной поток** | 1. Запросить снятие. 2. Система требует подтверждение. 3. После «да» — перевод, mood −5, корректировка fact.saved. |
| **Альтернативы** | A1: отказ в диалоге → без изменений. A2: без подтверждения → операция не выполняется. |

---

## UC-08. Выбрать / получить цель

| Поле | Содержание |
|------|------------|
| **Цель** | Иметь ориентир накопления и получить награду |
| **Предусловие** | Профиль есть; для claim — не `planning` и хватает savings |
| **Основной поток (выбор)** | 1. Открыть копилку. 2. Выбрать цель из списка трека. |
| **Основной поток (claim)** | 1. При достижении нажать получить. 2. Списание cost, mood/★ награды. |
| **Альтернативы** | A1: недостаточно накоплений → claim недоступен |

---

## UC-09. Выполнить задание периода

| Поле | Содержание |
|------|------------|
| **Цель** | Закрепить тему и получить награду периода |
| **Предусловие** | План подтверждён; задание в `activeQuestIds` и не закрыто |
| **Основной поток** | 1. Открыть задания. 2. Выбрать квест. 3. Ответить верно (или разложить корзины). 4. Система начисляет монеты/XP/★, закрывает квест. |
| **Альтернативы** | A1: неверно → объяснение, задание остаётся; XP за ошибку 1 раз; комбо сброс. A2: практика каталога → XP без монет. |

---

## UC-10. Пройти урок

| Поле | Содержание |
|------|------------|
| **Цель** | Изучить мини-историю и пройти проверку |
| **Предусловие** | Урок доступен треку |
| **Основной поток** | 1. Открыть «Учёба». 2. Пройти шаги. 3. Ответить на quiz. 4. При первом успехе — монеты/XP/★. |
| **Альтернативы** | A1: повтор → без повторной монетной награды. A2: неверный quiz → можно повторить по правилам UI. |

---

## UC-11. Закрыть период и увидеть итог

| Поле | Содержание |
|------|------------|
| **Цель** | Понять, насколько план совпал с фактом; получить последствия для питомца |
| **Предусловие** | Фаза `playing` |
| **Основной поток** | 1. Инициировать завершение (с учётом `nextAction`, напр. копилка). 2. `closePeriod`. 3. Экран summary: план vs факт, feedback, стадия/статы. |
| **Постусловие** | Фаза `summary`; начислен бонус за квесты при выполнении условий |
| **Альтернативы** | A1: система подсказывает следующее действие, если период «не готов» к хорошему закрытию |

---

## UC-12. Начать следующий период

| Поле | Содержание |
|------|------------|
| **Цель** | Получить доход и новый цикл планирования |
| **Предусловие** | Фаза `summary`; кулдаун истёк или demoMode |
| **Основной поток** | 1. Нажать «следующий период». 2. Начисление дохода, коррекция hunger, новый набор квестов, фаза `planning`. |
| **Альтернативы** | A1: вне демо до кулдауна → действие недоступно / таймер |

---

## UC-13. Открыть раздел взрослого

| Поле | Содержание |
|------|------------|
| **Цель** | Посмотреть прогресс и настройки опеки |
| **Предусловие** | Профиль есть |
| **Основной поток** | 1. Нажать иконку взрослого. 2. Решить арифметику. 3. Открыть панель прогресса. |
| **Альтернативы** | A1: неверный ответ → вход запрещён |

---

## UC-14. Включить демо-режим

| Поле | Содержание |
|------|------------|
| **Цель** | Пройти 2–3 периода подряд без ожидания |
| **Предусловие** | UC-13 успешен |
| **Основной поток** | 1. Включить переключатель «Демо-режим». 2. Система сохраняет `demoMode=true`. |
| **Постусловие** | Кулдауны периодов/квестов не блокируют |

---

## UC-15. Сбросить профиль

| Поле | Содержание |
|------|------------|
| **Цель** | Вернуть приложение к состоянию «с нуля» для демо/теста |
| **Предусловие** | UC-13 |
| **Основной поток** | 1. «Сбросить тестовый профиль». 2. Подтвердить. 3. Удаление ключей профиля и backup. 4. Онбординг/создание заново. |
| **Альтернативы** | A1: отмена диалога → без изменений |

---

## UC-16. Продолжить после перезапуска

| Поле | Содержание |
|------|------------|
| **Цель** | Не потерять прогресс |
| **Предусловие** | Профиль ранее сохранён |
| **Основной поток** | 1. Kill приложения. 2. Запуск. 3. Загрузка из SharedPreferences (или backup). 4. Главный экран с тем же прогрессом. |
| **Альтернативы** | A1: повреждён основной ключ → попытка backup (если реализовано в репозитории) |
