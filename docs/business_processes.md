# Бизнес-процессы и жизненные циклы

**Назначение:** описать процессы «как работает игра» языком аналитика: фазы, решения, ветвления.  
**Код:** `GamePeriod.phase`, методы `GameEconomy` / `GameController`.

---

## 1. Сквозной процесс «Первый запуск → уверенный цикл»

```
[Старт приложения]
        │
        ▼
  Профиль есть? ──нет──► Онбординг → Создание питомца → Save
        │да
        ▼
  [Главный экран]
        │
        ▼
  ┌─────────────────────────────────────────┐
  │  ЦИКЛ ПЕРИОДА (повторяется)             │
  │  planning → playing → summary → …       │
  └─────────────────────────────────────────┘
```

---

## 2. Жизненный цикл периода (state machine)

```
          confirmPlan
  ┌──────────────┐         ┌──────────────┐
  │   planning   │────────►│   playing    │
  └──────────────┘         └──────┬───────┘
                                  │ closePeriod
                                  ▼
                           ┌──────────────┐
                           │   summary    │
                           └──────┬───────┘
                                  │ startNextPeriod
                                  │ (+ доход, новые квесты)
                                  ▼
                           ┌──────────────┐
                           │   planning   │  (следующий номер периода)
                           └──────────────┘
```

| Состояние | Разрешено | Запрещено (типично) |
|-----------|-----------|---------------------|
| `planning` | Составлять план, смотреть главный/учёбу | Покупки, пополнение копилки как факт периода, закрытие с фактом |
| `playing` | Покупки, копилка, задания периода, закрытие периода | Менять зафиксированный план |
| `summary` | Смотреть итог, ждать/стартовать следующий | Новые траты периода |

## 3. Процесс BP-01: Планирование бюджета

**Владелец:** Ребёнок  
**Вход:** `balance`, трек  
**Выход:** `BudgetPlan`, фаза `playing`

| Шаг | Действие | Правило / шлюз |
|-----|----------|----------------|
| 1 | Открыть экран плана | phase == planning |
| 2 | Задать суммы корзин | ≥ 0 |
| 3 | (опц.) Рекомендация | доли по треку, remainder → savings |
| 4 | Подтвердить | Gateway: total ≤ balance **и** mandatory ≥ 1 |
| 5a | OK | confirmPlan → playing |
| 5b | Fail | Сообщение, остаёмся в planning |

**BPMN-логика шлюза (текст):** Exclusive gateway «План валиден?» → Да / Нет.

---

## 4. Процесс BP-02: Игровая фаза (параллельные активности)

После плана ребёнок может выполнять **в любом порядке** (AND-доступность, не жёсткий sequence):

| Активность | Условие выхода |
|------------|----------------|
| Задания периода | Верные ответы / soft fail loop |
| Магазин | Покупки при canAfford |
| Копилка | Transfer / withdraw / claim |
| Учёба | Независимо от периода (награды 1 раз) |

**Рекомендуемый happy-path для «хорошего» периода (жюри):**

1. План с ненулевой копилкой  
2. ≥1 верное задание  
3. ≥1 обязательная покупка  
4. Пополнение копилки  
5. Закрытие периода  

`nextAction` направляет к незакрытым условиям.

## 5. Процесс BP-03: Покупка

```
[Выбор товара] → phase==playing?
        │нет → отказ
        │да
        ▼
   canAfford(price)?
        │нет → feedback «не хватает»
        │да
        ▼
   [Подтверждение UI]
        ▼
   balance -= price
   fact.{kind}Spent += price
   hunger/mood += deltas
   if spent > planCap → mood -= 3
   save + feedback
```

---

## 6. Процесс BP-04: Задание

```
[Открыть квест]
      │
      ▼
  Ответ верный?
      │нет → объяснить; XP ошибки 1 раз; combo=0; квест OPEN
      │да
      ▼
  Режим = период?
      │да → монеты + XP + ★ + combo + skillBonus; CLOSE
      │нет (практика) → XP (меньше); без монет/★; CLOSE на период
```

Ротация набора: таймер 5 мин или сразу в demoMode.

---

## 7. Процесс BP-05: Закрытие периода и рост

```
[closePeriod]
      │
      ▼
 comparePlanFact → mandatoryOk, savedOk, planClose, wasGoodPeriod
      │
      ▼
 применить дельты mood/hunger/★ / бонусы квестов
      │
      ▼
 wasGoodPeriod? → goodPeriodStreak++
      │
      ▼
 streak ≥ 2 и stage < 3? → stage++, streak=0, ★+=2
      │
      ▼
 phase = summary; save
```

Численные пороги — [`economy_rules.md`](economy_rules.md) §7–§10.

## 8. Процесс BP-06: Следующий период

```
[startNextPeriod]
      │
      ▼
 demoMode OR cooldown elapsed?
      │нет → ждать (~2 мин)
      │да
      ▼
 balance += incomeForTrack
 hunger -= 8 (floor 10)
 новый GamePeriod (planning)
 pickPeriodQuests
 save
```

## 9. Процесс BP-07: Опека взрослого

```
[Иконка взрослого] → арифметика OK?
      │нет → отказ
      │да
      ▼
  Панель:
   • прогресс
   • demoMode on/off
   • звук
   • начислить монеты (лимит)
   • сброс профиля → confirm → clear keys → онбординг
```

## 10. Процесс BP-08: Сохранение и восстановление

| Событие | Действие системы |
|---------|------------------|
| Успешная мутация профиля | `ProfileRepository.save` (основной ключ + backup) |
| Старт приложения | load primary → если fail, backup |
| Сброс | clear primary + backup |

Ключи: `finny_profile_v1`, `finny_profile_v1_backup`.

## 11. RACI (роли по процессам)

| Процесс | Ребёнок | Взрослый | Система |
|---------|---------|----------|---------|
| План/покупки/копилка/квесты | R | I | A (правила) |
| Демо / сброс | I | R | A |
| Начисление дохода / рост | C (триггер кнопкой) | I | R/A |
| Контент JSON | — | — | R (загрузка); контент-автор вне runtime |

R = Responsible, A = Accountable, C = Consulted, I = Informed.
